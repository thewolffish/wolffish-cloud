A **capability** is one thing the agent knows how to do: a folder holding a `SKILL.md` — the
instructions it reads at runtime — and usually a plugin that carries the actual tools. The agent
picks a capability up when the work calls for it; you never load one by hand.

**35 capabilities** ship from your organization's registry today, plus two built into the app
itself. `Settings → Capabilities` lists exactly what this machine has, and admins can narrow the
list per person, team or role — see [Organization controls](/governance/org-controls).

## Files and documents

| Capability | What it does |
| --- | --- |
| `filesystem` | Read, write, edit and search files; diagnostics, replacements, unified diffs, formatting |
| `document` | Read, create, modify, convert and merge documents (docx, html, markdown, text) |
| `pdf` | Read, create, modify, merge, split, secure and compress PDFs |
| `spreadsheet` | Read, create, modify, analyse and convert xlsx, csv and tsv |
| `archive` | List, read out of, extract and create zip archives |
| `utilities` | Deliver a file to you as an attachment; push an openable folder or file card |

## Your screen

| Capability | What it does |
| --- | --- |
| `computer-use` | See the screen and control mouse and keyboard, with a verified-aim loop, element lookup through the accessibility tree, and evidence returned on every action |

Computer use works through a **shadow cursor** and background input, so the agent does not take your
real mouse while it works. While it can see your screen, the display carries a blue edge glow and a
centred "capturing your screen" pill — raised before the first capture, and cleared before the turn
can end. See [What your organization can see](/using/privacy).

## Voice

| Capability | What it does |
| --- | --- |
| `speech-to-text` | Transcribe audio with faster-whisper, 99 languages, entirely on this machine |
| `text-to-speech` | Generate voice memos with a local neural engine, entirely on this machine |

Both run **on-device**. No audio leaves the machine, and neither needs a key.

## Built in

Two capabilities are part of the app rather than the registry, because they are about the
conversation itself:

- **`changes`** — the undo. Lists the turns that edited files and restores one. See
  [Undo](/using/agent#undo).
- **`todo`** — the task list a multi-step turn draws as a checklist card.

## Services your organization runs

Four capabilities are backed by something the organization provides rather than by this machine
alone. You configure none of them, and no key is ever on your device.

| Service | Where it runs | How to check it |
| --- | --- | --- |
| **Web search** | The organization's search lane | `Settings → Services → Brave Search` shows ready, your searches today and the organization's month |
| **Computer use** | This machine, under OS permissions | `Settings → Services → Computer Use` shows which permissions are granted |
| **Speech-to-text** | This machine (local engine) | `Settings → Services` shows the model and its download state |
| **Text-to-speech** | This machine (local engine) | Same |

## Adding your own

Two paths, and they are different in kind:

- **Your own capability.** In `Settings → Capabilities`, drop a `SKILL.md`, a capability folder or
  a `.zip`. It becomes yours alone — it syncs to your other devices and nobody else sees it. Every
  drop is validated before anything is written, so a failed import cannot half-install.
- **An MCP server.** `Settings → MCP` connects an external tool server; its tools join the agent's
  catalog live.

For a capability the whole company should have, ask an admin to publish it to the registry —
[Capabilities](/sync/capabilities) covers how that works.

<Note>
Capability folders are mirrored from the registry, so a folder you edit by hand inside the org scope
is replaced on the next sync pass. Edit the source and publish it, or import it as your own.
</Note>
