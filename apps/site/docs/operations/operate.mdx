## Three layers of verification

| Layer | Command | Needs |
| --- | --- | --- |
| Typecheck + desktop seam tests | CI, on every push | Nothing |
| Local smoke suites | `npm test` in `apps/api` | `wrangler dev` + the mock hosts |
| The live gate | `node scripts/verify-live.mjs` | The deployed edge |

### CI

`.github/workflows/ci.yml` typechecks `apps/api` and `apps/desktop`, lints the desktop, and runs the
seam tests that need no network: config last-write-wins, second-device restore, capability sync, the
purge cycle, the usage ledger, mobile channel settings, channel status.

### Local smoke suites

```bash
# terminal 1–3
npx wrangler dev --port 8787
node scripts/mock-deepinfra.mjs
node scripts/mock-brave.mjs

# terminal 4
npm test
```

Runs `smoke-auth`, `smoke-admin`, `smoke-sync`, `smoke-search`, `smoke-ai`, `smoke-archive` in order.
The suites that `PATCH` the org are followed by a pause before the router suite, because org policy
is cached at the edge for up to 60 seconds and a back-to-back run would trip the allowlist checks on
stale policy.

### The live gate

```bash
WFC_DEMO_PASSWORD=… node apps/api/scripts/verify-live.mjs
```

Every scenario against the deployed edge, pure API — no direct database writes and no test-mode
bypass anywhere. It signs in as the seeded service owner, invites a throwaway employee through the
real flow, exercises it, and leaves it suspended with all sessions revoked.

Real model calls are capped at 30 output tokens (500 for the reasoning matrix), so the whole suite
costs fractions of a cent.

### Load

`node apps/api/scripts/load-500.mjs` simulates 500 employees running long agentic sessions at once
— the shape the gates were built for. Watch `GET /admin/gates` while it runs: the correct behaviour
is queue depth rising and latency growing, never errors.

## The nightly run

Cron `17 3 * * *` UTC. Each job is bounded by its own deadline, and together they stay well inside
the 15-minute allowance; a backlog drains over successive nights rather than overrunning.

| Job | What it does |
| --- | --- |
| `sessions` | Delete session rows 30 days past expiry |
| `reset_codes` | Delete expired password reset codes |
| `pairings` | Delete pairing offers older than a day |
| `gc_blobs` | Collect orphan R2 objects |
| `purge_deleted` | Purge records of conversations deleted 30+ days ago |
| `archive_idle` | Move records of conversations idle 14+ days into gzipped R2 blobs |
| `retire_usage` | Export and delete raw usage rows past 180 days |

Run it on demand with `POST /admin/maintenance/run` — the same bounded jobs, audited, for an
operator draining a backlog.

## Troubleshooting

<AccordionGroup>
  <Accordion title="A user says the model picker is empty or wrong">
    Read their effective policy: an empty allowlist means "the org default model only", not
    "everything". Check `PUT /admin/users/:id/policy` and `PATCH /admin/org`. Remember an edit takes
    up to the edge cache window — about a minute — to land on devices.
  </Accordion>

  <Accordion title="Calls are slow but not failing">
    That is the design. Check `GET /admin/gates`: rising queue depth with hosts at their concurrency
    means the organization is at capacity, and calls are waiting rather than erroring. More real
    capacity comes from more hosts in `MODEL_UPSTREAMS`, never from more keys on one account.
  </Accordion>

  <Accordion title="Calls are being refused">
    Look at the `decision` column in `usage`. `denied_model` is the allowlist; `denied_quota` is a
    cap. `GET /admin/usage` shows the totals, and the caps are on the user's policy row falling back
    to the org row.
  </Accordion>

  <Accordion title="Search reports itself unconfigured">
    The lane needs `BRAVE_API_KEY` or `SEARCH_PROVIDERS` as a Worker secret, and `search_enabled` on
    the org row. `GET /v1/search/status` distinguishes the two: `configured` is the key,
    `enabled` is the switch, `ready` is both.
  </Accordion>

  <Accordion title="A user's settings keep reverting">
    The desktop adopts any config row stamped by someone else before re-pushing its own. If an
    admin's repair is not sticking, confirm it went through `PUT /admin/users/:id/config` — that is
    what mints the fresh server stamp. See [Desktop sync](/sync/desktop).
  </Accordion>

  <Accordion title="A phone shows content but cannot send">
    Two different failures. `GET /v1/bridge/status` says whether the desktop is on the bridge; the
    phone's own socket says whether the organization is reachable. A phone that can read but not run
    a turn has a reachable organization and an absent desktop — start the desktop.
  </Accordion>

  <Accordion title="The browser extension will not connect">
    Confirm the desktop is running and unlocked, that both sides name the same port (default
    `23152`), then reload the extension. Debug logs are at
    `~/.wfc/workspace/logs/extension/.debug/<date>.log`.
  </Accordion>

  <Accordion title="A desktop is missing capabilities, or has stale ones">
    A sync pass only swaps folders when no agent run is active; it parks and retries otherwise. Check
    `GET /v1/capabilities/manifest` against the machine's `<cerebellum>/.wfc-caps.json`, and run
    `seed-capabilities.mjs --check` to confirm the registry still matches `capabilities/`.
  </Accordion>

  <Accordion title="Someone left the company">
    Suspend the account and revoke its sessions — they are separate acts. Suspension stops future
    sign-ins; revocation kills the sessions that already exist, closes bridge sockets and drops push
    registrations. Both are audited.
  </Accordion>
</AccordionGroup>

## Observability

Worker observability is on and **metadata-only**: request bodies are never logged by handler code.
What you get is errors, latency and the platform's own structured events — the nightly report, gate
decisions, metering failures. For anything about spend, read the [usage ledger](/governance/audit)
rather than the logs.
