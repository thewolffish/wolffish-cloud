---
title: "نشر مستأجر"
description: "اشتق، وضع علامتك، وانشر تحت حساب Cloudflare الخاص بالمستأجر"
---

نموذج النشر **اشتقاق لكل مستأجر**. لكل منشأة اشتقاقها من المستودع، وحسابها في Cloudflare، ومفاتيحها،
ونطاقها. لا نسخة مشتركة، ولا صورة من هذا تجلس فيها بيانات مستأجر بجوار آخر.

ولا شيء في شيفرة الوكيل يتغيّر بين مستأجر وآخر — تتغيّر نقطة النهاية والعلامة، وللهاتف المعرّفات التي
تعتمد عليها المتاجر.

## ١. أنشئ الموارد

في حساب Cloudflare للمستأجر، ثم ضع معرّفاتها في `apps/api/wrangler.jsonc`:

| المورد | الاسم |
| --- | --- |
| قاعدة D1 | `wfc-master` |
| نطاقا KV | `wfc-auth`، `wfc-config` |
| دلو R2 | `wfc-blobs` |
| نطاق مخصص | اسم مضيف الواجهة للمستأجر |

يقرأ سطح المكتب `API_BASE` من `apps/desktop/src/main/cloud/api.ts`، ويمكن تجاوزه أثناء التشغيل
بـ `WFC_API_URL`.

## ٢. اضبط الأسرار

بـ `wrangler secret put`، ولا تُودَع في المستودع أبدًا:

| السر | الغرض |
| --- | --- |
| `JWT_SECRET` | سر توقيع HS256 لرموز الوصول |
| `DEEPINFRA_API_KEY` | مضيف النماذج — أو `MODEL_UPSTREAMS`، قائمة JSON بالمضيفين |
| `BRAVE_API_KEY` | خطة البحث — أو `SEARCH_PROVIDERS`، قائمة JSON بالخطط |
| `RESEND_API_KEY` | بريد المعاملات لرموز استعادة كلمة المرور |
| `CONFIG_ENC_KEY` | ٣٢ بايتًا عشوائيًا بترميز base64 — يختم كل صف إعدادات متزامن عند التخزين |
| `EXPO_ACCESS_TOKEN` | اختياري؛ فقط إن فرض مشروع Expo أمان الإشعارات المعزَّز |

```bash
openssl rand -base64 32   # CONFIG_ENC_KEY
```

<Warning>
احذف المتغيّر `ADMIN_RESET_CODE_READ` من `wrangler.jsonc`. فهو يتيح لمسؤول قراءة رمز استعادة معلَّق،
وهو موجود فقط ليثبت اختبار الإصدار تدفّق البريد من طرفه إلى طرفه. وبدونه يجيب المسار بـ 404.
</Warning>

## ٣. رحّل وانشر

```bash
cd apps/api
npm run db:migrate:remote
npm run deploy
```

`deploy` يفحص الأنواع أولًا، فيوقف خطأ الأنواع الإصدار بدل شحنه.

## ٤. أنشئ أول مالك

إمّا أن تشغّل بذرة العرض — وهي تُنشئ كادرًا من ٥٠ شخصًا مفيدًا للاستعراض — أو تستبدل بها بذرة بمالك
واحد:

```bash
WFC_DEMO_PASSWORD=… npm run seed:remote
```

ثم ادعُ الباقين عبر `POST /admin/users` من سطح مكتب المالك. وإن استخدمت بذرة العرض فبدّل كلمة مرورها
واحذف التعبئة المسبقة من نموذج الدخول في
`apps/desktop/src/renderer/src/pages/auth/AuthGate.tsx`.

## ٥. انشر القدرات

```bash
node apps/api/scripts/seed-capabilities.mjs
```

عملية آمنة التكرار. و`--check` حارس الانحراف في CI؛ و`--prune` يحذف أيضًا مدخلات السجل التي لا مجلد
لها في `capabilities/`. انظر [القدرات](/ar/sync/capabilities).

## ٦. تحقّق

```bash
WFC_DEMO_PASSWORD=… node apps/api/scripts/verify-live.mjs
```

كل السيناريوهات أمام الحافة المنشورة، عبر الواجهة البرمجية فقط، بلا أي تجاوز لوضع الاختبار. انظر
[التشغيل](/ar/operations/operate).

## ٧. أعد علامة تطبيق الهاتف

الهاتف **تطبيق منفصل لكل مستأجر**، لا تطبيق مشترك. وكل معرّف ثابتٌ في أعلى
`apps/mobile/app.config.ts`:

| الثابت | ما يحدّده |
| --- | --- |
| `APP_NAME` | اسم العرض |
| `APP_SCHEME` | مخطط الرابط |
| `PACKAGE_IDENTIFIER` | معرّف الحزمة / اسم الحزمة |
| `EXPO_PROJECT_SLUG` | مشروع Expo |

<Warning>
إن غيّرت `APP_SCHEME` فعليك تغيير `DEEPLINK_SCHEME` في **نسختَي** ملف البروتوكول —
`apps/mobile/src/lib/bridge/protocol.ts` و`apps/desktop/src/main/cloud/bridge-protocol.ts` —
وهما متطابقان بايتًا ببايت بحكم العقد. والانحراف هناك انشقاق في البروتوكول.
</Warning>

ثم:

- `npx eas init` تحت حساب Expo للمستأجر لإنشاء مشروعه وكتابة `EXPO_PROJECT_ID`. وهو يُشحن `null` عن
  قصد، فتتوقف عمليات البناء وتسأل بدل النشر تحت مشروع شخص آخر.
- وجّه البناء إلى حافة المستأجر بـ `EXPO_PUBLIC_API_URL`.
- لإشعارات أندرويد، سجّل الحزمة الجديدة في مشروع Firebase للمستأجر، واستبدل `google-services.json`
  وأزل التعليق عن `googleServicesFile`. أما iOS فيكفيه اعتمادات EAS.
- استبدل الأيقونة وشاشة البدء تحت `apps/mobile/assets/images/` — فالفن المرفق مشترك مع النسخة الشخصية.

## ٨. احسم أمر وضع العرض

وضع العرض في الهاتف جولة تعمل بلا اقتران، وتُقدَّم من شبكة توصيل محتوى. إمّا أن تعيد بناءه وتنشره على
شبكة المستأجر (`node scripts/demo/build-demo-bundle.mjs` في `apps/mobile` ثم ضبط
`EXPO_PUBLIC_DEMO_BASE_URL`) أو تحذف مدخله من الباب. وتركه على حاله يوجّه كل تثبيت إلى حزمة المستودع
الأصلي.

## أين يُحاسَب الاستدلال والبنية التحتية

كلاهما على المستأجر مباشرة، بأسعار مزوّديه:

- **الاستدلال** — على حساب النماذج الخاص به، على نقطة نهاية بلا احتفاظ بالبيانات. لا يمر عبر وولفيش
  ولا يحمل هامشًا.
- **البنية التحتية** — على حسابه في Cloudflare: العامل، وD1، وR2، وKV، وكائنات Durable. ولا معالجات
  رسومية في هذا البند، لأن الوكلاء ينفّذون على أجهزة الموظفين.
