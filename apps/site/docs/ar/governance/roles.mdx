أربعة أدوار، بتراتب ثابت:

| الدور | يقرأ بيانات الإدارة | يعدّل | ملاحظات |
| --- | --- | --- | --- |
| `owner` | نعم | نعم | الدور الوحيد الذي يمسّ مالكًا أو يُنشئ واحدًا |
| `admin` | نعم | نعم | لا يمسّ مالكًا |
| `support` | نعم | **لا** | طبقة العرض فقط |
| `employee` | لا | لا | حسابه وبياناته فقط |

يسافر الدور على رمز الوصول ويعيده `/v1/me`، فيعرف العميل هل يرسم ضوابط الإدارة. **وهذا عرض فقط.**
فكل نقطة نهاية إدارية تعيد التحقق من الدور على الخادم؛ وإخفاء زر ليس ضابطًا.

<Note>
لا توجد وحدة إدارة ويب منفصلة. واجهة الإدارة تعيش داخل تطبيق سطح المكتب الخاص بالمسؤول، أمام
الواجهة البرمجية نفسها التي يستخدمها أي عميل.
</Note>

## إدارة الأشخاص

| الإجراء | نقطة النهاية | من |
| --- | --- | --- |
| الدعوة | `POST /admin/users` | owner, admin |
| القائمة/القراءة | `GET /admin/users`، `GET /admin/users/:id` | owner, admin, support |
| تعديل الدور والحالة والملف | `PATCH /admin/users/:id` | owner, admin |
| استعادة كلمة المرور | `POST /admin/users/:id/reset-password` | owner, admin |
| مسح قفل جهاز | `POST /admin/users/:id/clear-pin` | owner, admin |
| إبطال كل الجلسات | `POST /admin/users/:id/revoke-sessions` | owner, admin |

الدعوة تنشئ الحساب وتصدر كلمة مرور مؤقتة؛ وأول دخول يفرض كلمة مرور شخصية. وتعليق الحساب وإبطال
جلساته فعلان منفصلان — التعليق يمنع الدخول لاحقًا، والإبطال يقتل الجلسات القائمة. وإخراج موظف عادةً
هو الاثنان معًا.

## سياسة النماذج

يضبط `PUT /admin/users/:id/policy` قائمة مستخدم وسقوفه، ويضبط `PATCH /admin/org` الافتراضات التي
يرثها الجميع. وسياسة المستخدم الفعّالة هي صفّه حيث توجد قيمة، وإلا فصف المنشأة.

وتستقر التعديلات على الأجهزة خلال نافذة الذاكرة المؤقتة للحافة — دقيقة تقريبًا — لأن التعديل الإداري
يحذف النسخة المخزَّنة في KV. انظر [الحصص والتطبيق](/ar/governance/quotas).

## إصلاح إعدادات مستخدم

هذا مسار الدعم لحالة «تطبيقي يتصرّف بغرابة»، لأن صف الإعدادات المتزامن **هو** إعدادات سطح مكتب
المستخدم:

- `GET /admin/users/:id/config` يقرأه حرفيًا. وهو فوق طبقة الدعم، ولا يفتح مسؤولٌ صفَّ مالك،
  و**الإفصاح نفسه مدقَّق** — وهو القراءة الوحيدة المدقَّقة في الواجهة — لأن الصف يحمل أسرار تكاملات
  المستخدم.
- `PUT /admin/users/:id/config` يكتبه، أو يعيده إلى الصفر بـ `{"config": {}}`. وختم الخادم الجديد
  الذي يصدره هو ما يجعله يستقر: يتبنّى سطح المكتب أي صف ختمه غيرُه قبل أن يدفع نسخته، فيبقى إصلاح
  المسؤول عبر إقلاع المستخدم التالي بدل أن يموت تحت كتلة عميل قديمة. ومدقَّق **بالحجم فقط** —
  فالمحتوى أسرار المستخدم ويبقى خارج السجل.

## صف المنشأة

يحمل `GET` / `PATCH /admin/org` الافتراضات:

| الحقل | المعنى |
| --- | --- |
| `name` | اسم المنشأة |
| `default_model` | ما يحق لمستخدم بلا قائمة استدعاؤه |
| `default_allowed_models` | القائمة الافتراضية |
| `user_daily_token_cap` | رموز لكل موظف في اليوم بتوقيت UTC (٠ = بلا حد) |
| `org_monthly_token_cap` | رموز للمنشأة كلها في الشهر (٠ = بلا حد) |
| `search_enabled` | المفتاح الرئيسي لمسار البحث |
| `user_daily_search_cap` | عمليات بحث لكل موظف في اليوم |
| `org_monthly_search_cap` | عمليات بحث للمنشأة كلها في الشهر |

## مراقبة النظام

| نقطة النهاية | ما تجيبه |
| --- | --- |
| `GET /admin/usage` | إجماليات كل مستخدم من التجميع اليومي |
| `GET /admin/gates` | حالة البوابات الحية — عمق الطابور، والجاري لكل مضيف، وفترات الراحة |
| `GET /admin/audit` | سجل التدقيق |
| `POST /admin/maintenance/run` | تشغيل المهام الليلية الآن |
